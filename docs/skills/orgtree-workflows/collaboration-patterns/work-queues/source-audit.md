# Project mail queues: source audit

Checked against `2ec8c0e` on 2026-10-21. This is a documentation correction,
not a change to queue policy. It supersedes fixed-three-reminder wording and
unqualified one-job-per-listener descriptions in older notes.

All source paths below are under `engine/rs/orgtree-engine/src/` unless the
renderer path is written out.

| Subject | Current behavior | Source |
| --- | --- | --- |
| Assignment | Round-robin selects the least recently handed eligible listener; never handed first, then oldest registration. ACK skips halted agents, caps outstanding jobs by each listener's batch (1–20, default 1), and preserves pending eligible mail order. Busy/frozen mailboxes can still receive mail. | `domain/projects.rs:43`, `:221`, `:338`, `:376`, `:391` |
| ACK identity | An agent replies to the project using its handed copy's ID, once per job. Reclaimed copies cannot be acknowledged. Each ACK frees one place; reading a project mailbox is not an ACK or claim. | `domain/projects.rs:891`; `domain/mail.rs:448`, `:468`; `tools/project_inbox.rs:7` |
| Mode changes | Leaving ACK waives outstanding ACK requirements, including user jobs, without recording completion. Entering ACK does not retrofit earlier round-robin copies. Armed and paused agent listeners are notified, then dispatch runs. | `domain/projects.rs:980`; `domain/ops.rs:2198` |
| Reminders | `ack_reminders` is 1–10, default 3. With project `ack_timeout` and Runtime `working_checkups` on, each eligible checkup counts a reminder per outstanding job; a job already at its budget is reclaimed at the next checkup. These are inactivity/eligibility checks, not a precise elapsed-time deadline. | `domain/projects.rs:64`, `:77`, `:834`; `runtime/reminders.rs:157`, `:328` |
| Attempts and release | Each hand-out increments attempts. `max_attempts` is 1–100, default 3. A job becomes a dead letter on reclaim after exhausting attempts, not on its final hand-out. Halt, retirement, loss of reach or stopping/pausing the listener also release outstanding agent jobs. A spent one-shot still holds its own unacked batch. | `domain/projects.rs:90`, `:444`, `:592`, `:702` |
| Separate gates | Runtime `working_checkups` gates dead-letter enforcement on automatic reclaim and manual take-back. Project `ack_timeout=false` disables idle-timeout reclaim; it does not prevent release/take-back from dead-lettering an exhausted job while checkups are on. With checkups off, release/take-back returns it to pending even beyond the attempt limit. | `domain/projects.rs:651`, `:702`, `:851`; `domain/ops.rs:2635` |
| Turn-end nudge | Default on, separately configurable. Once per held assignment after the copy was consumed and a successful ordinary turn ends; not after interrupt/kill/compaction/session end/error/limit/freeze. A nonempty blocked status set since assignment suppresses this immediate nudge. It does not consume the checkup reminder budget and is independent of both timeout switches. | `domain/projects.rs:98`, `:1312`; `runtime/actor.rs:7763` |
| Take back | User or project ancestor only; a confirmation in the desk. Requeues at the front, preferring another eligible listener and falling back to the former holder, or dead-letters at the attempt limit with checkups on. The holder is told and its old ACK is refused; its process is not killed. User-held jobs cannot be taken back, even by the user. | `domain/ops.rs:2607`; `domain/projects.rs:231`, `:1575` |
| Who is told | A dead letter emits `project.dead_letter` and sends separate system mail up the parent chain through project nodes to the first real-agent ancestor if live; otherwise it falls back to the user. It does not broadcast the job to members or notify the original sender automatically. | `domain/projects.rs:748`, `:810` |
| Event subscribers | An armed `event` watchdog on `project.dead_letter` (or a matching prefix such as `project.*`) can notify an agent above/below the project. Org visibility alone is insufficient. This is distinct from `project_listener` on a project's manually fired event and from `fair_queue` consuming its mailbox. | `runtime/watchdogs/events.rs:184`, `:201`; `runtime/watchdogs/events.rs:9` |
| Dead Letter Line | Mail → listeners shows up to 200 armed/paused event watchdogs on `project.dead_letter` or `project.*` whose owners reach the project and whose patterns match the synthetic project-only event line. Paused entries are visible, not active recipients; payload-specific patterns may not appear in this preview. It is a subscriber list, not a list of jobs or a processor assignment. | `domain/projects.rs:1450`, `:1462`; `domain/ops.rs:2596` |
| List/read/resolve | User and agents above/below the project may list/read/retry/drop; agents need team or watchdogs enabled. Default list: 50 open entries, newest first; limit 1–100 and offset. `include_dropped` adds dropped entries; exact read accepts them too. Retry resets attempts and queues after commit, retaining history/retry records. Drop requires a reason, removes the open count and remains readable; a dropped letter cannot be retried directly. | `domain/ops.rs:2724`, `:2740`, `:2754`, `:2768`; `domain/dead_letters.rs:24`, `:135`, `:156`, `:170`; `tools/defs.rs:110` |
| Desk availability | Dead letters tab appears only while open count > 0. Show dropped works within that available tab; after the final open letter is resolved, use the tool to inspect dropped history. Details show body/history; retry/drop do not undo earlier effects. | `feed/compute.rs:65`; `apps/desktop/renderer/src/canvas/projectdesk.tsx:87`; `apps/desktop/renderer/src/canvas/deaddesk.tsx:36` |
| Inbox history | Project reads are side-effect-free. Omitted folder on list means waiting only; explicit inbox/sent enables history. `status=dead-letter` includes dropped dead-letter records, unlike the default open-only project action. Filters/cursors remain bound to caller/project/folder/status. | `tools/project_inbox.rs:7`, `:12`, `:35`, `:119`, `:185` |
| Purge | User or project ancestor retracts currently pending/unassigned mail, including jobs returned after an earlier attempt. Held, ACKed and dead-letter records remain. It is not a way to erase dead letters or reclaim a running job. | `domain/ops.rs:2708`; `domain/projects.rs:875` |
| User participation | The user's queue registration shares round-robin and batch accounting. Jobs arrive in the user's inbox. Reading is not an ACK. Leaving removes the registration but leaves held jobs until the user acknowledges; no idle/halt/retire reclaim or take-back applies. Exclude-sender covers user self-posts too. | `domain/projects.rs:243`, `:350`, `:608`, `:934`; `domain/ops.rs:2627`; `domain/ops/user_regs.rs:347` |
