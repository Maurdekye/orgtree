# Delegate and supervise

Keep work yourself when delegation would require more explanation than the task, or when the decision depends on context only you hold. Delegate a bounded objective when another worker can make useful independent progress. Write the deliverable, allowed scope, acceptance evidence and escalation point; distinguish the worker's role from its current assignment using [hiring](../hiring/SKILL.md).

Give each piece one responsible owner and collaborators with clear boundaries. Use the existing docket item for that work; assignment is ownership, while participation is collaboration. Avoid two agents unknowingly editing the same files or assuming the other is carrying a blocker. The exact access and assignment rules are in [work](../../docket/tool-work/SKILL.md).

Supervision starts with [reading reports](../../inspection/reading-reports/SKILL.md), not asking for a narrative already available in a transcript or draft. Check the actual evidence file before repeating a claimed result. Ask only for missing information or a decision the record cannot answer; a question wakes another model turn, while a read does not require that worker to reconstruct its history.

Use your superior for decisions outside your remit unless the user directly addresses you or an applicable audience authorizes user contact. A visible peer is not automatically under your management. Consult [chain and audiences](../../mail/chain-and-audiences/SKILL.md) for mail reach and [reaching the user](../../user/reaching-the-user/SKILL.md) for human-facing communication. Organization-specific instructions can narrow that route further.

When you need the superior to act, send a concrete message with the docket slug, evidence and requested decision. For FYI progress, prefer a passive notice. On completion or a blocker, update the item and report status; avoid repeated status questions while the worker's existing evidence already answers them.
