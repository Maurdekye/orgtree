## Architecture dependencies to preserve

1. **Durable domain first:** organization -> node identity/generation/session -> scope and credit holdings -> mail/request/work/document identities. `schema.py` and `ledger.Org` own these contracts. Retire/rehire, rename, compaction and provider changes must not accidentally reuse another generation's composer, session or authority.
2. **Persistence boundary:** SQLite is current default (`store.py:111`), one database per org, transactional save and row-backed/lazy logs behind `load_org`/`save_org`; scratch, transcript and outbox artifacts remain files. JSON reader, migration refusal and backend-mismatch guards still exist. A fresh v2 schema is possible, but old-data import/rollback is a separate explicit deliverable, not something this inventory proves. Never interpret incompatible data as an empty organization.
3. **Execution boundary:** a command passes authorization and durable admission before provider dispatch. Supervisor handles process lifecycle, resume, interrupts, mid-turn input, pending model changes and compaction; adapters normalize provider-specific behavior. Warm processes are an optimization, not proof of cache reuse. Native host paths and Docker paths cannot be treated interchangeably.
4. **Mail custody and ordering:** durable journal drain -> provider ingress -> acknowledgement -> persisted transcript. `_journal_drain` (`supervisor.py:6913`), `_owned_segments` (`:6996`), `_confirm_delivered` (`:7242`) and `commit_steer` (`:23705`) retain ownership and order during reconstruction/retry. Mail delivery is at-least-once; an HTTP acceptance is not proof the agent consumed it. Operation receipts (`opreceipts.py:578`) also distinguish application/admission from uncertain retries.
5. **Presentation contract:** canonical typed events and stored human/agent text are different concerns. Preserve variant validation, actor provenance, structured hidden machine segments, readable legacy fallback and full digest members. Excluding public access removes that exposure feature, not the need to separate agent instructions from human conversation.
6. **Live client contract:** REST snapshots plus WebSocket updates (`api.py:9295`), shared refresh bus and per-agent conversation store reconcile pending sends, streaming and durable history (`convo.ts:419`, `:632`, `:701`). A reconnect/reload needs snapshot recovery; animation and local ghosts must not become the authoritative ledger.
7. **Window ownership:** graph, desk, switchboard, pins and popouts share one desk owner keyed by org/node/generation. Establish that owner before implementing multiple windows. Browser persistence stores layout/composer drafts; it does not replace server state or imply question-draft persistence.
8. **Resource evidence:** adapter -> timestamped usage/capability observation -> freeze/routing decision -> truthful UI. Keep unknown, expired, unsupported and measured distinct. Do not transplant `accounts.py` or build a replacement multi-account registry for the prototype. Preserve distinct provider/harness/account identities only as an architectural seam; future management must be symmetric and provider-agnostic.
