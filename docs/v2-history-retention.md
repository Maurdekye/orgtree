# Retained history in v2

The 7 September user decision keeps history, documents and work records until manual removal. The copied SQLite store reconciles list deletions into real row deletions: the old ledger caps were permanent loss, not hidden display windows.

V2 removes automatic record eviction for agent/user/organization mail, notices, presented documents, delivered mid-turn messages and receipts, turn failures, turn usage and oracle history. Turn diagnostic files are no longer deleted when later attempts exceed the former 60-file ring. Watchdog events have a durable row-backed history while each active watchdog retains its small graph preview.

The History toolbar opens bounded pages of chat transcripts, mail, notices, presentations, events, mid-turn messages, errors, watchdog history and turn records. Agent selectors include archived generations. SQLite history collections use existing row sequence identities, including tied timestamps; removed or reordered cursor anchors return an explicit refresh response. JSON rollback data and embedded records use checked list cursors. Pages contain at most 100 records (the browser requests 50). Normal graph snapshots still carry only ten presentation cards and eight turn summaries per node, plus full document counts. Organization and agent document galleries page 100 metadata rows and fetch bodies separately.

Documents and watchdog history use the existing lazy SQLite row tables. Old SQLite document blobs remain readable and transition through the normal store save. JSON reader/rollback and backend-mismatch guards remain in place. Work records already archive without deletion; their manual deletion behavior is unchanged. Chat reads reuse the existing provider transcript projection, with bounded response pages and without the ordinary chat endpoint's 1000-message reach limit.

Limits: history removed by v1 before import cannot be recreated. Turn diagnostics retain their existing per-record telemetry bounds, and historical source fields already captured as summaries remain summaries. The application does not reconstruct information the harness never wrote. Lazy ledger writes still materialize the touched collection, and chat projection can scan the source transcript; this change bounds returned pages and graph payloads, not every internal read or node-document size. Explicit document replacement/dismissal, item deletion, and node/organization removal keep their existing manual semantics.

Validation uses fresh explicit HOME, USERPROFILE and ORGTREE_DATA for every storage process. Tests cross the actual production caps, reopen data in a second process, and retrieve oldest bodies through product APIs for SQLite and JSON. Fixtures include 1005 transcript messages, 135 mails, 115 read user mails, 205 org mails, 825 notices, 105 documents, 55 steer receipts, 45 errors, 25 turn usage records, overflow watchdog fires and 65 diagnostic files. Further tests exercise tied timestamps, appends during paging, cursor expiry after manual deletion, old SQLite document blobs, real inbox-read routes, gallery node filtering, and bounded tree previews. The renderer test clicks Older/Newer, changes collection/agent and recovers from an expired cursor.

Review follow-up: the History document rows reuse `DocumentDownload` and `MockupOpen`. A targeted Electron test adopts the actual History component into a native blank popout and verifies original download bytes, server-provided filename, the owning main window's authenticated fetch, and HTML opening in the shell's restricted artifact viewer. The fixture uses synthetic HTTP content and the real renderer/shell components, with no provider calls. Run `node tools/test-history-native.mjs` (set `ORGTREE_HISTORY_ELECTRON` if the test executable is external to this checkout). Its retained JSON evidence records the observed adopted-popout fetch status separately from the unregistered-window refusal; it does not claim all adopted-popout requests are unsigned. The shell owner independently confirmed that Chromium attributes trusted same-origin adopted-frame requests to the owning main frame; separate artifact and unregistered-window boundaries still apply.

Prior generations are stored node records: `_archive_session_in_place` inserts the predecessor at `org.nodes[pred_id]`, and `lineage_stack` walks those records. The real cheap-compaction/restart test proves that current generation 1, archived predecessor generation 0 and an ordinary retired agent are all selectable and yield distinct transcript contents. An unknown generation returns 404 rather than substituting the current session.
